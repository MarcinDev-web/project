# Job System

The Job System provides a robust way to execute tasks asynchronously, utilizing Web Workers for heavy background processing (like physics or mesh generation) and the main thread for render-critical or idle tasks.

## Features

- **Priority-based Scheduling**: Tasks can be scheduled with `RenderCritical`, `Background`, or `Idle` priority.
- **Worker Pool**: Automatically manages a pool of Web Workers for background execution.
- **WASM Support**: Built-in support for executing Rust-compiled WASM modules in workers.
- **Task Cancellation**: Support for cancelling pending or running tasks.
- **Idle Execution**: Runs low-priority tasks during browser idle time.
- **Worker Reuse**: Smartly reuses workers with the same loaded scripts to minimize overhead.

## Usage

### Basic Usage

```typescript
import { JobSystem, TaskPriority } from '@engine/core/job';

const jobSystem = new JobSystem(4); // Initialize with 4 workers

// Schedule a task
const handle = jobSystem.schedule({
  priority: TaskPriority.Background,
  execute: async () => {
    // Task logic here
  }
});

// Wait for completion
await handle.await();
```

### WASM Tasks (Rust Integration)

The system includes a `WasmJob` helper to easily run WASM modules in the worker pool.

```typescript
import { JobSystem, WasmJob } from '@engine/core/job';

// 1. Create a WASM task configuration
const physicsTask = WasmJob.create({
  // Path to the WASM glue JS file (generated by wasm-pack)
  moduleUrl: '/assets/wasm/physics_engine.js',
  
  // Name of the exported function to call
  functionName: 'step_simulation',
  
  // Arguments to pass to the function
  args: [deltaTime],
  
  // Path to the generic JobWorker script (from build output)
  jobWorkerUrl: '/assets/workers/JobWorker.js'
});

// 2. Schedule execution
const handle = jobSystem.schedule(physicsTask);

// 3. Wait for result
await handle.await();
```

### Task Priorities

- `RenderCritical` (0): Executed immediately on the main thread. Use for tasks that must complete within the current frame.
- `Background` (1): Executed in a Web Worker. Use for heavy computations (physics, pathfinding, procedural generation).
- `Idle` (2): Executed during browser idle periods (`requestIdleCallback`). Use for non-critical maintenance tasks (cleanup, prefetching).

## Architecture

### `JobSystem`
The central manager that maintains queues for different priorities and a pool of `WorkerPool` objects. It handles scheduling, worker assignment, and lifecycle management.

### `JobWorker`
A generic Web Worker implementation (`packages/core/src/job/worker/JobWorker.ts`) capable of dynamically loading ES modules (including WASM glue code) and executing requested functions.

### `WasmJob`
A helper class that standardizes the creation of tasks intended for `JobWorker`. It also provides a fallback implementation to run the WASM logic on the main thread if Workers are not supported (e.g., in some test environments).

## Integration Notes

1. **Worker Script Path**: Ensure `JobWorker.js` is built and available as a static asset.
2. **WASM Modules**: Your Rust crates should be built with `wasm-pack build --target web` to generate the compatible glue JS.
3. **CORS**: Worker scripts and WASM modules must be served with appropriate CORS headers if loaded from a different origin.
