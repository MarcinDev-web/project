# Phase 3: Collision performance and robustness

## Goals

- Reduce candidate checks via better broad-phase.
- Cut GC pressure with pooled typed arrays and SoA reuse.
- Improve Worker ergonomics (cancellation, backpressure) and telemetry.
- Keep identical behavior and fallbacks.

## Key changes

- Rust: add uniform grid (or sweep-and-prune) broad-phase; accept TRS SoA, output indices.
- TS: buffer pooling and subarray support in `@engine/wasm-collision`.
- Worker: request queue with AbortSignal and time-slicing.
- Editor: dynamic path selection thresholds and perf metrics overlay.
- CI: perf budgets with regression checks.

## Target files

- `crates/collision/src/lib.rs`
- `packages/wasm-collision/src/index.ts`
- `apps/editor/src/workers/collisionWorker.ts`
- `apps/editor/src/wasm/collisionWorkerClient.ts`
- `apps/editor/src/editor/placement/CollisionDetector.ts`
- Docs: `docs/ADR/ADR-wasm-collision.md`

## Acceptance

- ≥3x speedup vs Phase 1 for 1k candidates (median of 5 runs).
- No functional diffs on parity tests (1k randomized cases).
- No UI hitch on placement preview (no frame >16ms in smoke run).
